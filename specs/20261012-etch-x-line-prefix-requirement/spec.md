## 目的、現況與證據

本次只補齊需求與小工作排序，不修改程式、不匯入資料、不發布。

原本 `SPC-ETCH-X-TASK-001/002` 暫緩原因是 `X-` 的來源欄位與判定規則未完整。使用者本次補齊規則：咬蝕量 Excel 的「線別」欄位或線別標題若以 `X-` 開頭，該線別區塊資料不用匯入 SPC；未以 `X-` 開頭的線別資料都需匯入。

已檢查 `docs/SPC文件/PD-3-581-06B-咬蝕量_2026.xlsx`：

- 活頁簿共有 196 張日期工作表。
- 實際出現 `X-` 線別樣式：
  - `X-PT-01`
  - `X-PT-01-2`
  - `X-PT-01-3`
  - `X-PT-01-4`
  - `X-PT-02`
  - `X-QE-01`
  - `X-QE-02`
- 同一活頁簿也有未帶 `X-` 的正常線別，例如 `PT-01`、`PT-02`、`QE-01`、`QE-02`，這些仍需匯入 SPC。

- 本次不發布 SPC 測試站或正式站。
- 本次不延伸處理其他未定義的不生產、停線、免檢文字；若未來出現非 `X-` 的排除標示，另開需求。

## 系統責任與資料契約

### TransFiles

- 解析咬蝕量 Excel 時必須保留原始線別文字，例如 `X-PT-01`、`X-QE-02`。
- 判定欄位以 trim 後的原始線別文字為準；若以 `X-` 開頭，該線別區塊標示為 `ExcludedFromSpc=true`，排除原因為 `X-線別不匯入SPC`。
- `X-` 線別不得被正規化成一般 SPC 線別後送出，例如 `X-PT-01` 不得改成 `PT1` 或 `PT-01` 後送到 SPC。
- 預覽結果需可讓使用者辨識正常待匯入線別與排除線別；同一工作表可同時包含兩者。

### Portal

- 預覽與確認匯入必須沿用同一份排除判定結果，不可預覽排除、確認時又送出 SPC。
- 可保留批次追溯、使用者操作紀錄與排除摘要，但確認匯入時不得呼叫 SPC 寫入 `X-` 線別。
- 若同一日報全部線別皆為 `X-`，Portal/TransFiles 可回報「無需匯入 SPC 的有效線別」，不得視為 SPC 匯入失敗。
- 若同一日報同時有 `X-PT-01` 與 `PT-01`，正常線別仍需依既有嚴格新增/相同略過/衝突拒絕規則處理。

### SPC

- SPC 後端目前 `EtchReportSyncService.Rule` 只接受 `PT1`、`PT2`、`QE1`、`QE2`；TASK-002 不應把 `X-` 線別送進該服務，也不應新增 `X-` 線別機台或管制項目。
- 若外部仍直接呼叫 SPC 測試匯入 API 並傳入 `X-` 線別，SPC 可維持既有驗證拒絕；主要防線在 TransFiles/Portal 的預覽與確認匯入契約。
- 不新增資料庫 schema、不批次刪除或補標歷史資料。

## TASK-001 測試案例矩陣

| 測試類型 | 案例 | 預期 |
|---|---|---|
| Happy Path | 同一工作表含 `X-PT-01` 與 `PT-01` | `X-PT-01` 顯示排除且不送 SPC；`PT-01` 仍送 SPC。 |
| Happy Path | 線別 `X-QE-01`、`X-QE-02` | 兩者皆排除，不建立 SPC 量測資料。 |
| Boundary | 線別前後有空白，例如 ` X-PT-01 ` | trim 後仍排除。 |
| Boundary | `X-PT-01-2`、`X-PT-01-3`、`X-PT-01-4` | 皆排除，不去掉 `X-` 後匯入。 |
| Regression | `PT-01`、`PT-02`、`QE-01`、`QE-02` | 未帶 `X-` 的既有線別仍依原規則匯入。 |
| Invalid Input | 空白線別或未知線別 | 沿用既有預覽錯誤或略過規則，不因本需求新增推定。 |
| Direct SPC API | 直接傳 `X-PT-01` 到 SPC 測試匯入 API | 可維持既有不支援線別錯誤；不得建立測量資料。 |

TASK-002 至少需建立自動化測試覆蓋：線別判定 helper、預覽結果排除摘要、確認匯入不送 SPC、未帶 `X-` 線別回歸。

## 回復與補救方式

- TASK-002 若僅調整預覽/確認送出邏輯，rollback 可回復該次程式提交並重新發布測試站。
- 本需求不做 schema migration；若測試站誤匯入 `X-` 線別資料，需依 `SourceReference`、日期、線別與 UploadBatch 先輸出清查結果，再另行授權清理，不在 TASK-001/002 自動刪除。
- 正式站與正式資料不在本批授權內。

## 測試規劃

- Happy Path：
  - 同一工作表同時含 `X-PT-01` 與 `PT-01`，只匯入未帶 `X-` 的線別。
  - `X-QE-01`、`X-QE-02` 也被排除。
- Boundary Case：
  - 線別前後有空白仍以 trim 後判定。
  - `X-PT-01-2`、`X-PT-01-3`、`X-PT-01-4` 等延伸名稱仍排除。
- Invalid Input：
  - 空白線別、未知線別沿用既有錯誤或略過規則，不因本需求新增推定。
- Regression Risk：
  - 不可把 `X-` 線別去掉前綴後混入正常線別統計。
  - 不可影響未帶 `X-` 的既有咬蝕匯入流程。
  - 若預覽與確認匯入口徑不同，會造成使用者確認後資料量不一致，需自動化測試覆蓋。
