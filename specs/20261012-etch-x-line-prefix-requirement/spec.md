# 功能規格：咬蝕量 X- 線別不匯入 SPC 規則補齊
- 功能 ID：SPC-ETCH-X-LINE-PREFIX-20261012
- 版本：1
- 狀態：可實作
- 涉及專案：SPC、TransFiles、Portal
- 授權依據：使用者於 2026-10-12 指定 `docs/SPC文件/PD-3-581-06B-咬蝕量_2026.xlsx` 中線別若帶 `X-` 前綴，例如 `X-PT-01`，表示該線別資料不用匯入 SPC；沒有 `X-` 的資料都需匯入，其他線別以此類推。
- 現行需求基準：`docs/requirements.md`、`CHANGELOG_CUSTOM.md`
- 前案或相關規格：`specs/20261007-new-work-items/spec.md`、`specs/20261007-skip-etch-x-task/spec.md`、`specs/20260918-transfiles-etch-upload/spec.md`

## 目的、現況與證據

本次只補齊需求與小工作排序，不修改程式、不匯入資料、不發布。

原本 `SPC-ETCH-X-TASK-001/002` 暫緩原因是 `X-` 的來源欄位與判定規則未完整。使用者本次補齊規則：咬蝕量 Excel 的「線別」欄位或線別標題若以 `X-` 開頭，該線別區塊資料不用匯入 SPC；未以 `X-` 開頭的線別資料都需匯入。

已檢查 `docs/SPC文件/PD-3-581-06B-咬蝕量_2026.xlsx`：

- 活頁簿共有 196 張日期工作表。
- 實際出現 `X-` 線別樣式：
  - `X-PT-01`
  - `X-PT-01-2`
  - `X-PT-01-3`
  - `X-PT-01-4`
  - `X-PT-02`
  - `X-QE-01`
  - `X-QE-02`
- 同一活頁簿也有未帶 `X-` 的正常線別，例如 `PT-01`、`PT-02`、`QE-01`、`QE-02`，這些仍需匯入 SPC。

## 範圍與非範圍

範圍：

- 定義咬蝕量 Excel 匯入時 `X-` 線別前綴的排除規則。
- 調整既有咬蝕 X- 小工作狀態與排序。
- 定義後續實作需要涵蓋的預覽、確認匯入、驗證與回歸。

非範圍：

- 本次不修改 TransFiles、Portal 或 SPC 程式。
- 本次不匯入、刪除或補標任何既有資料。
- 本次不發布 SPC 測試站或正式站。
- 本次不延伸處理其他未定義的不生產、停線、免檢文字；若未來出現非 `X-` 的排除標示，另開需求。

## 測試規劃

- Happy Path：
  - 同一工作表同時含 `X-PT-01` 與 `PT-01`，只匯入未帶 `X-` 的線別。
  - `X-QE-01`、`X-QE-02` 也被排除。
- Boundary Case：
  - 線別前後有空白仍以 trim 後判定。
  - `X-PT-01-2`、`X-PT-01-3`、`X-PT-01-4` 等延伸名稱仍排除。
- Invalid Input：
  - 空白線別、未知線別沿用既有錯誤或略過規則，不因本需求新增推定。
- Regression Risk：
  - 不可把 `X-` 線別去掉前綴後混入正常線別統計。
  - 不可影響未帶 `X-` 的既有咬蝕匯入流程。
  - 若預覽與確認匯入口徑不同，會造成使用者確認後資料量不一致，需自動化測試覆蓋。
