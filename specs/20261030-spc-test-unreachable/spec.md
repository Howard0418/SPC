## 問題、預期行為與範圍
使用者回報 SPC 測試區無法連結。需先區分 DNS／IIS binding／TLS 憑證／靜態前端／API 健康端點／瀏覽器 Token 等層次，再做最小修正。修正後測試區可由指定測試入口開啟，前端資源與 API 可正常回應；其他測試功能維持原行為。

本次範圍限定：SPC 測試 Web、SPC 測試 API、本機 IIS 測試綁定與測試前端設定。明確不修改正式站、正式資料庫、正式憑證或正式 Portal。

## 需求與驗收
- R-001：確認測試入口網址、DNS、IIS 站台狀態、443／8901 binding、TLS 憑證與實體路徑。
- R-002：確認測試 Web `index.html`、`assets/*.js`／`*.css` 不被 fallback 成 HTML，且 API `/api/health` 可回應。
- R-003：若涉及 SSO，確認測試 Portal Launch 目標與測試 SPC API／前端環境一致；不得以正式端點替代測試端點。
- AC-001：Given 測試站設定完成，When 開啟測試入口，Then HTTP/TLS 成功且頁面可載入。
- AC-002：Given 測試頁面載入，When 查詢必要 API，Then API 回應成功或顯示可讀錯誤，不出現空白頁／MIME 錯誤。
- AC-003：測試站修正不得變更正式站設定、資料庫或發布內容；既有正常功能回歸不受影響。
