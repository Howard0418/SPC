## 目的、現況與證據

### 已確認需求

1. 左側可點擊頁面與「作業人員與權限主檔維護」的頁面權限必須使用相同名稱，且實際可見／可進入行為不可互相矛盾。
2. Portal「咬蝕量日報輸入」的厚度量測格線必須能從 Excel 複製貼上，仍由使用者檢查後按原儲存按鍵送出。
3. SPC 建立落塵監控資料錄入頁；第一、二列為欄名，第三列起為資料貼上區，資料可預覽、檢查後再確認寫入。
4. 三項變更不得破壞既有 Portal 日報、SPC 計算、管制圖、通知、權限及其他正常頁面。

### 程式觀察

- SPC 後端 `SpcPagePermissions.Catalog` 只列出部分頁面；前端 `App.vue` 左側選單包含更多可點頁面，Editor 選單大部分目前只依角色呈現。
- `/particle-monitoring` 目前沿用 `analysis.spc` 權限，權限清單沒有獨立的 Particle／落塵監控頁，因此畫面名稱與實際路由並非一對一。
- SPC 的咬蝕分析頁會連到 Portal `/QualityAssurance/EtchAmountEntry`；咬蝕原始日報由 Portal 保存，再同步 SPC。現行格線支援逐格、Enter 及 COM 自動填值，尚未處理 Excel 矩形貼上。
- SPC 已有 Particle Long Format、`ParticleMeasurements`、Particle preview／confirm API、C/U chart 與查詢分析頁；現行白名單及分析篩選為 R1～R9，使用者提供的表單畫面則涵蓋到 R12。

## 範圍與非範圍

### 範圍

- 以同一頁面登錄表對齊 SPC 左側選單、權限清單、路由守門與三語名稱。
- 維持既有使用者目前實際可用頁面；若新增權限碼，需以受控對照補齊原本已具備的有效存取，不得誤刪或擴權。
- Portal 咬蝕 A／B side 格線支援從目前游標格貼上 Excel 的 Tab／換行矩形資料。
- SPC 新增「落塵監控資料輸入」頁，採固定雙層表頭與第三列起的格線貼上，沿用 Particle preview／confirm 契約。
- Particle Location 擴充為 R1～R12；既有 R1～R9 歷史資料、查詢與圖表保持不變。

### 非範圍

- 正式站、正式資料與正式權限不異動；本輪只發布 SPC 測試站。
- 不改咬蝕量、ER、均勻性、線速建議或 SPC 同步公式。
- 不改 Particle C/U-chart 統計公式、既有歷史量測、TransFiles 匯入或現有圖表資料。
- 不把左側群組標題、純導向別名或外部連結誤列為獨立頁面權限。
- 不例行更新 Excel 進度表。

## 建議貼上格式

### 咬蝕量日報

- 在 A side 或 B side 的任一 `BEFORE`／`AFTER` 格開始貼上。
- PT1／QE1 每組 5 個 OP，建議每列貼 10 欄：`OP1 BEFORE, OP1 AFTER ... OP5 BEFORE, OP5 AFTER`，共 5 列。
- PT2／QE2 每組 10 個 OP，建議每列貼 20 欄，共 5 列。
- 不貼「咬蝕量」計算欄；系統仍以 `BEFORE－AFTER` 即時計算。
- 僅接受數字或空白；超出 A/B side 邊界、非數字、負數或 `BEFORE < AFTER` 必須標示位置並阻擋儲存，不能部分靜默截斷。

### 落塵監控

- 畫面固定兩列表頭，不建議由使用者修改：
  - 第 1 列：第一欄為「量測時間」，其後每四欄依序為 R1～R12。
  - 第 2 列：每個 Location 固定為 `0.5 µm／1 µm／5 µm／10 µm`。
- 第 3 列起貼資料；建議一列共 49 欄：`量測時間 + R1～R12 × 4 粒徑`。
- 量測時間建議使用單一儲存格 `YYYY/MM/DD HH:mm`，不要在同一格以換行分隔日期與時間；系統以台灣時區轉為含 `+08:00` 的時間送預覽。
- Count 只接受大於等於 0 的整數；`0` 是有效量測，空白代表缺值且不得自動補 0。
- 若複製內容包含相同的前兩列表頭，系統可辨識後略過；表頭名稱或順序不同時應拒絕並指出差異。
- 截圖最右側似有作業員文字欄，但現行 Particle 模型沒有獨立業務作業員欄。本階段以登入者作稽核身分，不把該文字混入 49 欄矩陣；若需保存「實際量測人員」，執行前需提供確切欄名與一列範例，再決定新增批次欄位或資料模型。

## 例外與邊界

- 權限目錄不能只改顯示文字；路由守門、左側顯示及 API 權限必須用同一權限碼判定。
- 既有 `analysis.spc` 同時涵蓋 Particle 的行為需在相容對照中拆開；既有已能看 Particle 的人員須保持相同有效存取，但不得因此取得其他分析或輸入權限。
- 貼上支援 Windows／Excel 常見 Tab、CRLF 與 LF；不接受把千分位、單位或備註混在數值格內。
- 咬蝕貼上只改前端草稿，仍沿用原儲存 API、完整列數檢核及 SPC 同步狀態。
- Particle preview 建立的是暫存匯入批次；未按確認不得產生 `ParticleMeasurements`。
- 重複 Particle 預設整批拒絕；使用者明確選擇「略過重複」後才可寫入其餘有效值，不提供覆蓋模式。
- 新頁的「貼上清除」只清目前未確認草稿，不刪除已匯入量測。

- Given 使用者未取得某頁權限，When 左側選單產生或直接輸入該頁網址，Then 選單不顯示且 router guard 導向第一個已授權頁面。
- Given 安全管理者編輯自己的權限，When 嘗試新增稽核查閱／匯出／證據權限，Then 既有安全規則拒絕自我加權。

## BDD：咬蝕量格線貼上

- Given PT1／QE1 五個 OP 或 PT2／QE2 十個 OP，When 使用者在 A／B side 任一 BEFORE／AFTER 格貼上 Excel Tab 與換行矩形，Then 從目前格開始依列欄填入，立即重算咬蝕量，不自動儲存或同步 SPC。
- Given 貼上內容包含 CRLF／LF、數字、0 或空白，When 內容完全在當前 side 邊界內，Then 數字與空白均依原矩形套用，切換 side 後草稿保留。
- Given 貼上內容含非數字、負數、非矩形、超出五組或當前 OP 欄位，或導致 BEFORE 小於 AFTER，When 使用者貼上，Then 顯示 side／組次／OP／欄位錯誤，本次貼上零套用且不送出 API。
- Given 貼上成功後使用者按原儲存按鈕，When 畫面建立原有日報 payload，Then `points` 與逐格輸入的結構相同，COM、Enter 移動、日報載入與 SPC 同步流程不變。

## BDD：落塵監控格線貼上

- Given 使用者具有 `data.particles` 且貼上一列 49 欄，When 系統解析時間與 R1～R12 四粒徑，Then 空白略過、0 保留，Long Format 來源座標可追溯到原列欄。
- Given 貼上內容含兩列表頭，When 表頭與固定格式完全相同，Then 略過表頭；任一名稱或順序不同時整批拒絕，不建立 preview。
- Given 資料含非整數、負值、無效時間、欄數錯誤或非矩形內容，When 使用者要求預覽，Then 顯示錯誤且不部分送出。
- Given preview 無驗證錯誤，When 使用者確認，Then 才寫入 `ParticleMeasurements`；遇既有量測預設拒絕，明確選擇略過重複後只新增非重複資料。
- Given TransFiles 使用既有 Particle 匯入流程，When 新網站貼上頁發布，Then TransFiles 契約、既有 R1～R9 資料與 C/U 統計公式保持不變，分析與比較範圍擴充至 R12。
- Given 使用者開啟落塵監控資料輸入頁，When 畫面顯示量測位置與貼上操作，Then R1～R12 配置圖位於貼上區上方，兩區都有可辨識框線，圖片等比例縮放且不遮住貼上控制項。
- Given 貼上區尚無資料，When 使用者查看畫面，Then 固定顯示日期時間／位置及 R1～R12 × 0.5／1／5／10 µm 的黃色雙層表頭與空白貼上列，不再只顯示空白大文字框。
- Given 使用者聚焦格線後貼上合法 49 欄資料，When 前端完成解析，Then 每個值落在對應 R／粒徑格、日期與時間在第一欄分行顯示，且只有按「建立預覽」才呼叫 preview API。

## 假設與未決問題

- 不阻擋規劃：使用者提供的落塵截圖只顯示 R4～R12 區段；依既有表單與前案規格，第一版規劃完整 R1～R12。
- 不阻擋規劃：落塵資料第三列起的第一欄採「日期時間合併欄」。若現場實際會複製成日期、時間兩欄，實作前應提供一列純文字貼上樣本以補 parser 測試。
- 執行前需確認：截圖最右側的作業員欄是否要保存為業務資料；若需要，須提供欄名、用途及每列／整批規則，可能涉及 schema migration，不能自行推定。
