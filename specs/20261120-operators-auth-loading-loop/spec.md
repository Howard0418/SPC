## 目的、現況與證據

1. 已登入使用者進入測試站 `/operators`，人員表格停在「正在載入人員清單」。
2. 約第 7～8 秒主內容轉為空白，網址短暫變成 `/login?redirect=%2Foperators`。
3. SSO 返回 `/operators` 後，表格仍永久停在載入狀態，沒有可操作的錯誤訊息。

程式唯讀盤點顯示：`OperatorsView.load()` 以 `Promise.all` 同時讀取人員與權限目錄；共用 API 攔截器遇到 401 時，會導向登入並回傳一個永遠不完成的 Promise。只要其中一個請求進入此路徑，頁面的 `catch` 與 `finally` 都不會執行，因此載入狀態無法解除。此為目前最合理且與錄影一致的根因；實作階段仍須以自動測試及測試站網路請求確認是哪一支端點先回 401。

## 範圍與非範圍

### 範圍
- 統一 401／SSO 重導期間的請求生命週期，避免呼叫端永久 pending。
- 有效登入時，人員與頁面權限目錄均須完成載入。
- 登入逾期時最多重導一次；重新登入成功後自動回原頁並重新載入。
- 無法恢復時停止載入並顯示可理解的登入逾期或載入失敗訊息。
- 補齊頁面與共用攔截器測試，回歸其他使用同一 API client 的頁面。

### 非範圍
- 不變更任何人的角色、頁面權限或帳號資料。
- 不修改資料庫 schema、正式資料、AD／Portal 帳密登入流程。
- 不重構無關頁面或同時執行其他小工作。
- 正式區不在本件授權範圍；測試區完成後仍須人工重走錄影路徑。

## 需求與驗收
| 需求 ID | 業務規則 | 驗收 ID | 可觀察的通過條件 |
|---|---|---|---|
| R-001 | 有效登入不得被誤導回登入頁 | AC-001 | Given 有效 Editor token，When 開啟 `/operators`，Then 人員與權限目錄成功顯示，網址不跳轉且載入提示消失。 |
| R-002 | 登入逾期只能啟動一次受控重導 | AC-002 | Given token 逾期，When 任一必要 API 回 401，Then 只導向一次登入；SSO 成功後返回 `/operators` 並完成載入，不循環。 |
| R-003 | 所有失敗路徑都必須結束 loading | AC-003 | Given 401 無法恢復、403、500、逾時或其中一支平行請求失敗，When 請求結束，Then 頁面不會永久顯示載入中，並顯示可操作的錯誤／重新登入指引。 |
| R-004 | 修正不得改變既有權限與其他 API 行為 | AC-004 | Given 既有 Viewer／Editor 與頁面權限，When 完成修正並跑回歸，Then 權限判斷、編輯／刪除保護、其他頁面正常請求及環境隔離均維持原行為。 |

## 例外與邊界
- 兩支平行請求同時 401 時，仍只能產生一次重導。
- 一支成功、一支 401／403／500 時，不得顯示不完整資料為成功，也不得永久 pending。
- SSO 返回後 token 尚未穩定的短暫 401，須受有限次數／時間守衛，不得無限重試。
- 使用者無 `admin.operators` 權限時應顯示 403 或導向可存取頁面，不可偽裝成登入逾期。
- API 離線或環境錯置須使用既有錯誤訊息，不得導向登入循環。

## 假設與未決問題
- 錄影足以確認可觀察問題；確切先回 401 的端點待實作階段以測試站 Network／API log 驗證，不阻擋規劃。
- 預設沿用 Portal SSO，不新增本機登入或延長 token 有效期。
