# AD／工號登入使用同一 SPC 操作者
- 功能 ID：20260917-sso-single-operator；版本 1；狀態：防重複實作與測試發布完成；既有帳號關係待使用者確認。
- 依使用者需求修正 SPC SSO 防重複，只發布 release/test；Portal 僅唯讀追查，不修改。
## 現況與證據
AuthController 僅按 Username 比對；工號已有資料而帳號未連結時回 409。Portal SpcSsoTokenService 對失敗使用舊簽章且省略工號重試，SPC 舊流程可另建工號為 AD 帳號的 Viewer。測試庫目前 22 筆，未見明確重複組；已請使用者提供受影響帳號以核對，不能推定不同 AD 帳號為同一人。
## 規則與驗收
- R-001/AC-001：完整簽章的工號與 AD 可連結既有工號建檔（Username 空白、等於工號、或該次輸入為工號別名）；AD 大小寫/網域/UPN 正規化。交替登入只有同一個 ID，保留角色、頁面權限、停用狀態及關聯。
- R-002/AC-002：既有明確不同 AD 帳號、名稱/工號多筆衝突、停用/刪除帳號拒絕，不靠姓名或 Email 猜測合併；不自動删除歷史使用者或升權。
- R-003/AC-003：舊簽章只能登入既有同 AD 帳號，不能使用未受簽章保護的工號/部門/Email，也不能首次建立帳號，避免失敗重試產生第二筆；完整簽章保留合法首次建檔。
- R-004/AC-004：SQL Server 交易級 application lock 與程序內鎖序列化 SSO 配對/建檔；併發相同身分不重複，nonce 重放/錯誤簽章仍拒絕。
## 範圍與相容
僅 SPC AuthController、專屬測試與文件；無 schema migration。新 Portal 完整簽章已支援，既有 legacy 登入仍可用，但 legacy 首次建立改為拒絕並要求新版交換。確認同人而已形成兩筆的歷史資料，須先確認保留權限及關聯再合併，本次不猜測或刪除。
## 發布回復
備份測試 API，確認 test/PMR_SPC_TEST 後發布並保存設定。回復應用備份；本次無批次改資料，登入僅連結本人資料。
