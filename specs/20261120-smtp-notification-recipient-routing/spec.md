# SMTP 郵件通知依類型選擇收件人

- 功能 ID：`SPC-SMTP-RECIPIENTS-1120`；版本：2；狀態：001 已發布測試站，待人工收信驗收；002 尚未開始。
- 主系統：SPC Web／API。相依系統：若公式的實際提交入口由 Portal 代送，須先核對其責任與測試方式。
- 依據：2026-11-20 使用者要求。現行 SPC OOS／OOC 共用 `RecipientOperatorIdsJson`，無可用收件人時用 SMTP 預設地址。Portal 添加／稀釋管制值通知依品保／製程角色寄送，屬既有獨立事件。

## 頁面與格式建議

- 延用 `/settings/smtp` 的人員名單與部門篩選。建議用「收件人｜部門｜Email｜OOS（超出規格界限）｜OOC（超出管制界限）｜調整量公式修改｜濃度公式修改」矩陣，每列四個獨立勾選框。顯示各類已選數量，篩選後仍保留其他部門已選人員。
- 沿用作業人員主檔 Email。建議每人一個有效信箱，例如 `name@pmr.com.tw`；前後空白可去除，重複地址在同一事件內去重。空白、格式錯誤或停用人員標示原因，請先修正作業人員主檔再勾選。不同類型可選同一人。
- 本次未附 SMTP 設定頁截圖。實作時依現行頁面排版，若補附截圖，請提供「異常預警收件人」區塊並遮蔽密碼／個人信箱；驗收保留去識別的桌面及窄畫面。

## 需求與 BDD 驗收

- R-001／AC-001：Given A 只勾 OOS、B 只勾 OOC，When 儲存後重載並分別產生已提交的 OOS、OOC，Then 勾選狀態正確且各事件只寄給該類對象。現有 OOS／OOC 判定、事件建立與寄送時機沿用。
- R-002／AC-002：Given 舊版只有共用收件人或既有預設地址，When 首次開啟新版或切回舊版，Then OOS／OOC 按既有規則收信。建議新版 OOS／OOC 零有效收件人時顯示預設信箱回退與警示，公式類零勾選時明示不寄送。
- R-003／AC-003：Given 調整量或濃度公式有實質變更，When 相應的正式保存交易成功，Then 寄送對應類型，收件人來源為該欄；同次兩類變更各依類型路由。同值、預覽、只改備註及保存失敗不得寄送；寄送失敗不得回滾已保存公式。
- R-004／AC-004：Given 無效人員 ID、停用人員、無效郵件、重複地址或無權修改者，When 嘗試保存或寄送，Then 拒絕無權或無效的設定、指出可修正欄位，並在寄送時重新檢查人員有效性及地址去重。保留原有設定權限與稽核。
- R-005／AC-005：Given 既有 SMTP 驗證、密碼留白行為、測試信、報表、校正、Portal 管制值通知，When 新增分類收件設定，Then 這些流程依原契約運作。測試信沿用現有明確指定目標。

## 計畫、順序與回復

1. `SPC-SMTP-RECIPIENTS-1120-TASK-001`（P1）：先處理 OOS／OOC，核對寄送入口及舊資料回退，加入四欄勾選畫面與相容保存契約。公式欄在寄送功能就緒前清楚標示待啟用。測試既有收件人相容、權限與輸入檢核後才發布測試站。
2. `SPC-SMTP-RECIPIENTS-1120-TASK-002`（P2，依賴 001）：逐一核對調整量公式與濃度公式保存入口、版本啟用／排程與重送防重需求，再接已提交的異動通知。調整量公式和添加／稀釋管制值為不同事件；若需要調整 Portal，先記錄主責與相容發布順序。

- 001 將分類名單與 SMTP 表單一併寫入既有設定檔，保留資料庫中的共用名單供舊版和未設定分類時使用。無 schema migration。回復前版 Web／API 時沿用舊共用名單。
- 驗證：實作前建立路由和保存單元測試，後續做四類內容／收件對照、輸入邊界、舊設定相容、失敗保護及回歸。測試站 SMTP 驗收用指定測試信箱；實際網站發布依版本遞增及 Web／API 連線驗證規則。正式發布需另行授權。
- 001 實作、測試及發布證據見[驗證紀錄](verification.md)。002 的公式送信及保存接點仍待執行。
