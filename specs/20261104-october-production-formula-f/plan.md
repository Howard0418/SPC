## 系統責任與受影響檔案

新增一次性正式受控 runner 與測試；SPC 既有版本／F／排程服務負責資料契約。來源為已驗證十月 manifest 與來源完整抽取。正式資料庫只追加十月歷史／排程，不修改目前 PPC 配置、啟用 F、API、前端或 schema。

## 實作方式與需求對應

1. 先測環境、來源 hash、自然鍵唯一、同日衝突、NoChange、NA 隔離及保護表不變。
2. 由來源完整抽取建立十月日別公式＋完整 F 八格，並由正式主檔即時以業務鍵映射；同 PPC／日期有不同版本者整組隔離。
3. 建立／重用語意相同的 F 歷史與公式版本；排程整體比較相同即 NoChange，差異或既有重疊則停止。
4. 在單一 serializable 交易內套用；不更新正式目前配置或啟用 F 主表。
5. 寫後重跑 NoChange、代表值試算、保護表指紋、API／版本與資料查詢驗證。

## API、檔案格式及資料模型

不新增 API 或 migration。runner 輸入 manifest 只保存來源 hash、業務鍵、公式、日期、F 八格及預期現況；連線字串與備份路徑不提交。證據 JSON／資料快照留 Git 外。

## 相容性與風險

最大的風險是把測試 ID、目前 F 或單一公式倒套十月。以自然鍵、完整 F、台北日界與來源 hash 阻擋；正式已有排程但內容不同時不覆蓋。量測及既有版本只讀指紋保護。
