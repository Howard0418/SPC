# SPC-TEST-REFRESH-1123 正式資料取代測試資料

- 規格版本 1。功能入口為正式 SPC「作業人員與權限主檔維護」，只允許具獨立資料庫刷新權限的管理員。
- 使用者確認正式單向複製並取代現行測試庫資料，保留不同的測試環境設定。來源固定 PMR_SPC_2026，目標固定 PMR_SPC_TEST。表單與 API 不接受資料庫、路徑、命令或連線字串參數。
- 複製量測、主檔、公式與版本、F 表、業務排程、人員與業務權限、庫內稽核及其他業務資料。測試站連線、schema／migration、SQL principal、SSO／金鑰、通知設定、外部連線及排程投遞行為維持測試環境。
- 正式本機密碼雜湊不複製。以帳號或工號確切映射測試認證及保留設定的參考；無法唯一映射時預檢阻擋。正式歷史稽核保留原環境標籤。將會觸發外部設備、MES 或寄送的記錄需保留歷史並阻擋消費，測試原設定外的副作用須為零。
- 投遞中的暫存與私有附件應在預檢列帳。當資料庫存在外部檔案索引時，須明確驗證可獨立重現或拒絕套用，不建立無效關聯。

## 驗收

- Given 授權正式管理員，When 開啟維護頁並預檢，Then 顯示固定來源／目標、來源快照、替換筆數、保留與重新對應設定、阻擋項目。
- Given 預檢通過，When 同一管理員確認固定目標名稱，Then 獨立執行器取得全域排他鎖、暫停測試寫入、建立可驗證的前版備份，並只更新測試庫。
- Given 程序逾時、重送、來源結構變更、環境身分不符或合併驗證失敗，When 執行，Then 正式資料保持，測試庫交易回復或按前版備份受控還原，操作結果可查。並行請求只能執行一筆。
- Given 刷新後，When 核對測試站 API、資料量、完整性、設定、認證及外部輸出，Then 資料符合核准的來源快照，測試身分與通知行為維持。

2026-11-23 已授權建立獨立執行身分與隔離演練。來源只允許固定正式庫讀取，不啟用正式庫 snapshot isolation、不修改正式表、觸發器、設定或業務資料。目的地固定測試庫，實際刷新由上線後的管理員確認觸發。

2026-11-24 指定 `PMR\ihao_ting` 為刷新執行身分。先配置該 Windows 身分在 `PMR_SPC_TEST` 的備份權，完整置換仍透過待整合的固定作業。正式庫權限及資料維持，網站 API 身分與刷新身分分離。

## 先行發布入口

2026-11-23 使用者確認保留 P22077 為測試專用帳號。刷新時保留該筆測試人員與其原 ID、登入憑證及參照；若正式來源出現相同工號、登入帳號或 ID，停止並核對，避免撞號或轉移憑證。其他無法唯一對應的人員仍阻擋。

使用者於 2026-11-23 同意先發布停用按鈕。Given 可開啟作業人員頁，When 操作者查看頁面，Then 顯示「複製正式資料到測試區」及尚未開放執行的狀態。按鈕無事件處理與 API，正式與測試皆不可執行。後續正式執行仍須獨立權限與已驗證執行器。

## 隔離交接驗收

Given 有效確認票且沒有進行中的作業，When API 交接至受控的本機目錄，Then 以確認票 ID 建立唯一作業，獨立執行器可領取一次並回報成功或失敗，操作者可依原 ID 查詢。重送同一張票回傳同一作業；其他操作者不可查詢或領用確認票。此階段以合成案例驗證交接，不啟用站台入口或執行資料置換。

Given 本機佇列有已確認作業，When 啟動獨立隔離執行程序，Then 領取一筆，執行固定合成資料演練，並依程序退出狀態寫回結果。作業內容不得指定命令與 SQL 目的；沒有待領作業時不得啟動演練。此程序只供隔離驗證。

Given 本機開發環境已明示啟用隔離端點且啟用 JWT 驗證，When 指定操作者預檢、確認或查詢，Then API 僅交接固定合成演練，僅接受確認票及作業識別碼；其他操作者不得存取。正式與網站測試環境不註冊此演練端點。
本機維護頁隔離演練依序提供預檢、確認及狀態查詢。發行建置維持停用入口。
- Given 固定唯讀來源有未完成的統計作業，When 多表置換驗證完成並準備提交，Then 目標未完成筆數須與來源相同，且所有未完成作業的重試時間須等於隔離上限；不符時整批回復。
- 成對隔離演練於同一置換交易內比對測試保留欄位與觸發器指紋，不一致即回復。
- Given 合成目的庫進入維護，When 一般寫入身分嘗試連入，Then 連入被拒；維護身分仍可工作，正常完成或失敗離開後一般身分可再寫入。
- 成對副本須用實際測試 API 的 SQL 登入驗證限制模式拒絕及恢復後可寫入。驗證只使用演練副本及可回復交易。
- 成對副本模擬提交後驗證失敗時，從同批已驗證測試備份回復固定演練目標，驗證資料基準後才開放寫入。
- 實際刷新閘門須對固定測試庫，在同一連線核對排他鎖、限制存取、當批唯讀正式副本來源，以及停寫後建立並通過校驗的測試回復備份。預檢失敗不執行置換。
- 刷新流程須在置換前取得停寫及回復備份，置換開工後若失敗，一律先回復並驗證。回復失敗時保持停寫並回報人工接手。
- 69 表交易新增受控測試庫入口。須通過當批備份閘門，置換與保留表範圍須符合伺服器分類清冊。既有隔離入口仍只允許成對副本。
- 實際維護程序固定使用 PMR_SPC_TEST，同一維護會話持有可跨還原的鎖。正式快照來源通過核對後才停寫，回復驗證通過後才復寫。
- 啟用前須由實際維護身分執行不改資料庫存取狀態的預檢，核對來源備份 UUID、唯讀副本與回復備份磁碟容量。
- 管理者確認實際刷新時，受控命令必須明示固定測試庫。成對副本驗證通過後才啟動，同批正式備份限一小時內。停寫後重新對應現行測試人員與收件人，若仍有其他測試庫會話則停止。
- 正式入口須以獨立指定操作者與管理員配置啟用。預檢只讀維護程序發布的隔離預檢摘要，分開讀取摘要與寫入待辦；確認票綁定摘要雜湊及固定目標。每個預檢摘要只能建立一次刷新作業。
- 獨立維護命令只讀取受限目錄中的預檢與備份計畫，核對摘要、操作者與還原後的來源備份 UUID。每個來源備份只領取一次；不使用 API 送來的資料庫、路徑或命令。
