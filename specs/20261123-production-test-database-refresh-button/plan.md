# 技術計畫

- 設計：正式 Web 經既有身分驗證向正式 API 建立預檢及確認請求。正式 API 校驗當前應用角色、獨立權限、確認是否同一操作者，並記錄操作稽核。
- 執行：網站身分只可投遞固定作業與讀取狀態。備份、隔離快照及測試資料寫入由獨立執行器完成，使用分離的源庫唯讀／備份及測試維護身分。站台既有正式 API SQL 身分維持最小權限。
- 保留：以測試 schema 和設定為基底，從一份固定的正式快照取代資料。對照欄位、主外鍵、identity、不可變歷程與觸發器，逐類驗證，最後核對雙向差異與列數。測試設定參照人員使用穩定業務鍵映射。
- 驗證：先於隔離副本演練身分異動、不同 schema、歷程觸發器、備份失敗、中途失敗回復、並行、目的地誤置、通知／MES 副作用及網站檢查，再進測試網站驗證按鈕。實際刷新正式指向的測試庫只在按鈕確認後觸發。
- 回復：以操作 ID 定位測試前版備份，確認後續測試寫入再還原；復驗 API 環境及資產。保留源庫與其操作稽核。
- 一致性快照演練：以獨立的本機合成庫執行 COPY_ONLY／CHECKSUM、VERIFYONLY 及還原；在備份後改寫合成來源，確認隔離副本仍提供同一時間點資料，並以該副本輸入既有置換及回復演練。
- 執行權限演練：分離來源備份與快照讀取、隔離還原和目標寫入。使用本機資料庫模擬身分實際執行受限操作，核對來源寫入及目標設定修改權限均不存在。
- 部署前檢查：在測試主機執行固定來源及目標的唯讀目錄比對，驗證部署環境可讀兩庫結構及套用資料表分類。輸出政策分類統計與部署狀態，不輸出連線設定或行內容。
- 排他作業：在目標資料庫以固定資源名取得 session applock，同一連線持有至作業結束。隔離驗證兩條連線競爭時第二筆立即拒絕，並驗證釋放後可重新取得。
- 將上述鎖接入隔離置換流程，在更新前取得，持鎖至結果查回或失敗回復查回。演練檢查交易內鎖狀態及結束後釋放狀態。
- 部署前唯讀盤點來源待送 MES、待送或可重試的校正通知、非完成統計工作與校正證書索引。正式執行預檢仍須從同一份凍結來源副本重做；有待隔離或附件不可重現項目時，阻擋確認。
- 統計作業匯入測試目標時，非完成記錄的下次重試時間設為不可到達的 UTC 上限，阻止既有處理器重試。保留狀態、錯誤及嘗試次數；來源快照保留原重試時間。完成作業的全部欄位保持。
- 保留測試登入雜湊及通知收件人時，依測試作業人員 ID 查工號與登入帳號，以正式快照唯一對應。工號及帳號指向不同人、多人映射同一人或參照遺失時阻擋。
- 依測試庫外鍵計算父表優先的插入順序與反向刪除順序。保留表跨界外鍵、自我參照與循環分別列帳，供置換器在執行前驗證。
- 盤點兩庫的觸發器名稱、事件、狀態與本文簽章。隔離演練對合成不可變歷史表驗證維護交易內暫停、還原及失敗回復；正式觸發器不變更。
- 本文簽章不同時，使用 SQL 解析器比對語法詞彙，忽略詞彙間空白與註解，保留常值及識別字內容。無法解析或實質詞彙不同時不得視為相同。
- 在隔離庫落實多表交易，來源固定為此次演練的唯讀副本，目標持有排他鎖，按外鍵順序反向刪除及正向載入，再核對列數與雙向差異。
- 由目錄產生具名欄位計畫。可寫欄位含 identity 原值，排除 computed、rowversion、隱藏和系統生成欄。比對使用全部可寫欄並要求包含完整主鍵；不支援的比對型別須明確阻擋。
- 統計歷史投影由置換交易讀取固定唯讀副本，寫入及雙向驗證皆使用同一投影；失敗時和其餘置換表一起回復。
- 置換交易在刪除前重新查固定副本。若納入待送 MES、有待送或可重試校正通知、尚未重現的證書索引，應停止整批置換；歷史匯入前須驗證對應的隔離與附件供應。
- 將已驗證人員映射以參數交給隔離置換交易。刪除前保存在同一連線的暫存表，套用正式來源欄位與測試原登入雜湊，並原樣保留測試專用人員。
- 保留測試報表及告警設定，只對其中的收件人 JSON 陣列重新對應 ID。無效陣列或缺映射阻擋，順序與其餘設定保持。
- 啟用前以部署身分唯讀探測資料庫操作權限，辨識備份權、敏感歷史表能力及角色邊界。探測不核發權限、不執行刷新。
- 隔離置換器只在交易內暫停明示核准且目前啟用的歷史保護觸發器，逐表核對後於提交前恢復，其他觸發器保持原狀。
- 實機完整演練以同一批識別還原正式與測試備份。兩副本限維護存取，正式來源副本設唯讀、測試副本供置換。驗證備份來源、兩副本目錄與測試特有帳號，結束後只清理此次副本。
- 實機演練必須再由置換 SQL 在寫入前核對兩邊名稱、正確資料庫、唯讀來源及兩庫限制存取狀態，整批維持同一排他鎖。
- 預檢確認票以操作者、固定目的庫和預檢 SHA-256 綁定，有效十分鐘。每位僅保留最新一張，只有一次可換作業交接；重啟後須重新預檢。

## 2026-11-25 實際刷新執行分工

- 操作者身分觸發與查詢受控作業，測試庫備份由已授權的獨立身分建立；正式來源仍沿用既有維護備份交接。
- 置換需由固定的維護作業接手，驗證備份來源、目標及同批清單。測試寫入隔離須涵蓋測試 API、Portal 及批次寫入，並驗證可回復；僅暫停單一 IIS 站台無法證明隔離。
- 啟用前以隔離副本驗證指定身分呼叫固定作業、維護作業只認固定測試目標，以及回復後重新開放寫入；不得用增加 db_owner 或正式庫權限取代分工。
