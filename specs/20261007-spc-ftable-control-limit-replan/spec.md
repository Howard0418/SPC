# SPC F 表版本記錄與管制界線重算規劃

功能 ID：SPC-FTABLE-CL-REPLAN-20261007  
日期：2026-10-07  
狀態：規劃完成，待使用者確認後逐一執行  
涉及系統：SPC API、SPC Web、SPC DB

## Goal
將使用者提出的兩項 SPC 調整加入小工作池：
1. F 表也要加入可查詢、可追溯、可回復的版本記錄。
2. 切換「樣本標準差」與「系統標準公式」時，必須重新計算管制界線，避免 UCL/CL/LCL 不變造成錯誤判定。

## Scope
- 規劃 SPC 後續小工作、優先順序、驗收方向與風險。
- 依資料正確性優先，先處理管制界線重算問題，再處理 F 表版本記錄。
- 本次只更新 `TODO.md`、需求索引、變更紀錄與本規格。

## Out of Scope
- 本次不修改 SPC 程式、資料庫 schema 或 IIS。
- 本次不執行資料修補、不重算既有正式資料。
- 本次不發布測試站或正式站。

## Current Behavior
- F 表已有 `ChemicalFTableVersions`、`ChemicalFTableCells`、`ChemicalFTableReferences`，可維護啟用版本與 F 表儲存格值。
- 藥液公式已有獨立版本記錄與回復能力，但 F 表變更尚未規劃等同的歷史查詢/回復功能。
- 管制項目頁已有「樣本標準差法」與「系統標準公式」相關選項；使用者回報切換後管制界線沒有變。

## Expected Behavior
- F 表每次套用新版或修改啟用版本時，都能建立版本記錄，保存變更前/後儲存格值、版本代碼、修改人、修改時間、原因與回復來源。
- F 表版本可查詢與回復；回復後會更新啟用 F 表並保留回復紀錄。
- 切換樣本標準差與系統標準公式後，相關管制界線必須依新方法重新計算或清除舊固定界線後提示重新試算。
- 使用者在畫面上能看出目前管制界線是由哪個方法計算，避免誤以為已切換成功。

## Business Rules
- 管制界線會影響 OOC、能力指標與後續判定，公式方法切換後不可沿用舊方法算出的 UCL/CL/LCL。
- 若目前存在手動固定管制界線或分段管制線，系統需明確區分「固定/分段」與「統計試算」來源，不可靜默覆蓋。
- F 表屬公式共同參照資料，版本回復可能影響多個藥液項目，需提供影響範圍提示。
- 正式資料重算或正式站發布需另行授權。

## BDD
### Scenario: 切換標準差方法後重算管制界線
Given 管制項目已有合法歷史量測資料與目前 UCL/CL/LCL  
When 使用者將管制界線計算方式由樣本標準差切換為系統標準公式  
Then 系統必須依新方法重新計算或清除舊界線並要求重新試算，不得沿用舊 UCL/CL/LCL

### Scenario: 手動固定界線不被靜默覆蓋
Given 管制項目已設定手動固定 UCL/CL/LCL  
When 使用者切換標準差方法  
Then 系統必須提示固定界線與統計重算的差異，並要求使用者明確確認後才更新

### Scenario: F 表變更建立版本紀錄
Given 人員在 F 表維護頁修改 F!B3 的數值  
When 套用新版 F 表  
Then 系統必須建立可查詢的 F 表版本紀錄，包含變更前後值、修改人與修改時間

### Scenario: F 表版本回復
Given F 表已有多筆版本紀錄  
When 使用者回復指定版本  
Then 系統必須更新啟用 F 表內容，並新增一筆回復紀錄保留來源版本

## Test Planning
- Happy Path：有歷史資料時切換方法，UCL/CL/LCL 依新方法改變；F 表修改後產生版本紀錄。
- Boundary Case：樣本數不足、分段管制線存在、手動固定界線存在、F 表沒有任何變更。
- Invalid Input：無效公式、缺少 F 表儲存格、非法版本回復、未授權使用者操作。
- Regression Risk：既有藥液公式版本紀錄不可受影響；既有 F 表公式引用計算不可中斷；既有 SPC 圖表不可錯用舊界線。

## Risks
- 管制界線重算會影響 OOC、報表與歷史查詢結果，需先用自動化測試鎖住計算差異。
- F 表版本回復可能影響多個藥液項目，需顯示影響範圍並保留 rollback。
- 若現有資料已保存錯誤界線，是否要批次重算需另開資料修補小工作並取得授權。
