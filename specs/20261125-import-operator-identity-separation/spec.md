# SPC 量測匯入與登入主檔分離
- 功能 ID：SPC-OPERATORS-IMPORT-IDENTITY-1125
- 版本：1
- 狀態：P1 已入池，尚未實作。先完成測試與必要發布，才進行正式帳號退役。
- 主系統：SPC API 量測匯入。相依：現有匯入來源與 Portal／AD 既有登入流程。
- 來源：[正式重複主檔唯讀驗證](../20261125-production-operator-account-merge/verification.md)。

## 問題與界線

SPC 通用量測匯入可將 Operator 欄文字當工號、名稱及登入帳號，建立已啟用的編輯者。正式三組同名候選的非 AD 列均符合該寫入型態，且建立時間附近有已確認批次包含對應作業人員。正式工號唯一索引包含隱藏列，現有匯入查重可能漏掉舊列而失敗。目標是保留量測來源文字與匯入相容性，讓建立可登入身分維持在既有主檔授權及可信 SSO 流程。本件不直接整理已存在的正式帳號。

## 行為與驗收

| 前提 | 操作 | 預期 |
| --- | --- | --- |
| 匯入包含只有姓名或無法對應可信身分的作業人員 | 確認匯入 | 原有量測及人員文字可查；不建立登入帳號、編輯者或授權。 |
| 已有正式 AD 主檔，來源使用姓名、工號或空白 | 確認／重送匯入 | 保留量測和既有合法名稱或空值行為；同名不配對到他人的 AD 主檔；原有角色、啟用及權限維持。 |
| 來源空白、同名、重送或同時確認 | 驗證匯入與 SSO | 不建立重複登入身分，既有合法登入與人員主檔維護可用。 |
| 過去已有姓名帳號，含已退役或隱藏資料 | 執行預防功能 | 歷史量測、稽核及既有人員仍可查，個案清理由原工作核准處理。 |

## 執行與回復安排

先盤點通用匯入及相關呼叫端是否需要作業人員名稱清單，在核心程式調整前補既有行為及權限回歸。執行前補齊正式差異、驗證及回復計畫。若改動 API 行為，依既有規則發布 SPC 測試站並驗證 Web／API，正式發布仍另行授權，回復沿用應用程式快照。這次僅新增規格和待辦。
