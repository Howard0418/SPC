# 功能規格：藥液公式總覽與批次儲存頁
- 功能 ID：20261006-chemical-formula-overview-batch
- 版本：1
- 狀態：規劃完成，待實作
- 涉及專案：SPC
- 授權依據：使用者要求「請建一個頁面，可以看到所有線別，槽位，分析項目的藥液分析公式，方便核對公式正確，一次儲存，而不用一次一次進去調整」。
- 前案或相依規格：[藥液分析公式版本記錄與回復](../20261006-chemical-formula-versioning/spec.md)

## 目的、現況與證據

目的：提供一個集中頁面核對所有藥液線別、槽位與分析項目的公式，並支援一次儲存多筆公式，降低逐筆進入主檔編輯的操作成本。

現況觀察：
- `ChemicalAnalysisOverviewView.vue` 已存在「線別分析項目總覽」，目前可篩選、匯出 Excel、導向單筆 `PartProcessCharacteristicsView.vue` 編輯。
- 總覽頁目前只顯示濃度公式與設定狀態，尚不能直接編輯或批次儲存。
- 藥液公式仍儲存在 `PartProcessCharacteristics.ChemicalAnalysisConfigJson`。
- 既有單筆 `PUT /api/v1/part-process-characteristics/{id}` 已整合 `ChemicalAnalysisFormulaVersionService`，公式變更時會建立版本紀錄。
- 藥液公式版本查詢與回復 API 已在測試站完成，可作為批次儲存風險的回復保護。

## 範圍與非範圍

範圍：
- 擴充既有藥液總覽頁，顯示每筆 CHEM 項目的線別、槽位、分析項目與主要公式欄位。
- 支援在同一頁編輯藥液公式欄位並一次儲存多筆變更。
- 批次儲存需逐筆建立公式版本紀錄，沿用前案版本服務。
- 儲存前需顯示變更摘要，讓使用者確認會修改哪些項目。
- 儲存後需重新載入資料，顯示成功/失敗結果。

非範圍：
- 不改藥液公式語法與計算引擎。
- 不改既有量測資料或歷史計算結果。
- 不取代單筆主檔編輯頁；單筆頁仍保留。
- 不做 Excel 匯入公式批次更新。
- 不發布正式站。

## 需求與驗收

| 需求 ID | 業務規則 | 驗收 ID | 可觀察的通過條件 |
|---|---|---|---|
| R-001 | 使用者可在總覽頁看到所有 CHEM 線別、槽位、分析項目與公式欄位。 | AC-001 | 進入藥液總覽頁，可用現有篩選看到各 CHEM 項目的線別、槽位、分析項目、啟用狀態、公式內容。 |
| R-002 | 使用者可在總覽頁直接修改公式欄位。 | AC-002 | 修改濃度公式、調整公式、調整量公式或小數位後，頁面能標示該列已變更。 |
| R-003 | 一次儲存只送出有變更的 CHEM 項目。 | AC-003 | 點擊儲存時顯示變更摘要；確認後只更新有異動的列，未異動列不呼叫更新。 |
| R-004 | 批次儲存每筆公式變更都需留下版本紀錄。 | AC-004 | 批次儲存 2 筆公式後，兩筆各自可在版本紀錄查到一筆新版本。 |
| R-005 | 批次儲存需可部分失敗且清楚回報。 | AC-005 | 若其中一筆失敗，畫面顯示成功/失敗列與錯誤訊息；成功列不被誤標失敗。 |
| R-006 | 權限沿用 SPC 主檔編輯權限。 | AC-006 | 未登入或無編輯權限不可批次儲存；前端入口仍受 `editorOnly` 保護。 |

## 例外與邊界

- 空白公式是否允許：第一版沿用單筆主檔既有驗證，不新增更嚴格規則。
- 小數位需限制合理範圍，第一版建議沿用目前單筆公式 UI 的 0 到 8。
- 若後端偵測公式 JSON 無變化，不新增版本紀錄。
- 第一版可採「前端逐筆呼叫既有 PUT」降低後端改動；若需要交易式全成功/全失敗，再新增批次 API。
- 若使用者在載入後資料已被他人修改，第一版不做鎖定；儲存後以後端最新結果重新載入。

## 假設與未決問題

- 假設第一版以「可核對、可批次儲存公式欄位」為主，不同時加入進階公式驗算器。
- 假設批次儲存允許部分成功，並用版本紀錄與錯誤清單降低風險。
- 未決但不阻擋：是否需要未來支援 Excel 匯入/匯出後再回存公式，另開後續任務。
