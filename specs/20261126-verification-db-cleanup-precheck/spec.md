# 演練資料庫清理前複核

- 工作代號：SPC-VERIFY-DB-PRECHECK-1126
- 範圍：SQL Server 上第一批 7 個 SPC 藥液公式結構演練庫。全名見 [複核 SQL](precheck.sql)。
- 依據：使用者要求繼續演練庫清理盤點。前次盤點結果為 26 個候選，8 個暫保留、18 個待確認。這 7 個取自待確認組中已查到自身完整備份且 SQL Server 可見備份檔的資料庫。
- 影響：唯讀維運複核。涉及 SPC 演練庫，沒有 Portal 或 KM 變更，無網站發布。

## DBA 執行方式

1. 使用具有伺服器連線、資料庫定義和 SQL Agent 工作檢視權限的維運身分，在原 SQL Server 的 `master` 執行 [precheck.sql](precheck.sql)。先確認 `INSTANCE` 是盤點的 SQL 執行個體。
2. 查核 7 個 `CANDIDATE`。預期來源是 `PMR_SPC_TEST`，備份須是演練庫自己的完整備份，且完成時間晚於該庫最後一次還原。`GAP` 代表對應檢查未通過或未執行，空的 `REFERENCE` 結果只有在無相關 `GAP` 時才代表該項未找到引用。
3. 由有權驗證備份的維運身分在檔頭填入剛核對的 SQL 執行個體名稱，再將 `@VerifyBackups` 設為 `1` 執行。逐庫查看 `BACKUP_VERIFY`。`PASS` 代表 `RESTORE VERIFYONLY WITH CHECKSUM` 成功。若需要證明整庫可用，仍要在獨立環境實際還原驗證。
4. 維運與功能負責人補查遠端網站、應用程式設定、外部排程和動態 SQL。逐庫確認無依賴、驗證證據已保存及備份保留策略。通過後才整理刪除申請，仍需另行確認精確庫名與時間。

本機 IIS 已查 16 份設定，未找到這 7 個庫名。SQL 的連線與鎖定檢查只反映執行當下。SQL Agent 比對工作步驟指定的資料庫及命令中的庫名。跨庫引用檢查涵蓋可見的靜態相依與同義字，執行完仍須查上述外部相依。
