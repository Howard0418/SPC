# 功能規格：藥液歷史匯入「無法判定」盤點與受控補正

- 功能 ID：SPC-CHEM-HISTORY-JUDGMENT-1104
- 小工作：`SPC-CHEM-HISTORY-JUDGMENT-1104-TASK-001`
- 版本：5
- 狀態：執行中／T-001～T-003完成，T-004待執行
- 優先級：P0（資料正確性與可回復）
- 涉及專案：SPC（主系統、權威判定與歷史證據）、Portal（查詢顯示相依）、TransFiles（後續匯入格式相依）
- 授權依據：2026-11-04使用者要求說明藥液輸入查詢為何存在「無法判定」，配合截圖、提出格式建議，規劃後加入小工作且不要立即執行。
- 現行需求基準：[需求索引](../../docs/requirements.md)、[歷史查詢判定](../20261028-chemical-history-judgment/spec.md)、[新保存規格快照](../20261102-chemical-save-history/saved-spec.md)

## 目的、現況與證據

使用者截圖顯示2026/10/30多筆藥液資料的分析值為0.70～1.03，來源標示「歷史匯入（原量測人員未記錄）」且判定為「無法判定」；另一張截圖顯示目前C5清潔／酸浸硫酸主檔已有LSL、Target、USL。

目前程式觀察：`ChemicalHistoryQueryService`不以目前主檔規格重判舊資料。依序只採用與量測ID、PPC、初／複驗值一致的保存公式追溯、伺服器保存規格快照，或數值完全相符且含上下限的歷史SPC計算紀錄；證據缺少、損壞或不一致時回傳`Unknown／Unavailable`。這是避免主檔後來改版後污染歷史判定的既有安全規則。

因此，截圖可證明「目前主檔有規格」及「舊列沒有可顯示的權威判定」，但尚不能單靠畫面判定缺的是哪一種歷史證據，也不能證明目前80～120／8～12就是2026/10/30當日適用規格。實作前須唯讀盤點實際量測ID、PPC、來源批次、公式／F／規格版本及歷史計算紀錄。

## 範圍與非範圍

範圍：

- 盤點藥液查詢所有`Unknown／Unavailable`資料，按原因分類並輸出可修正清單。
- 對照量測日期當時有效的PPC、規格分段／版本、公式、F、初複驗及保存結果，判斷哪些資料具備可驗證的補判依據。
- 修正新匯入契約，要求可重建權威判定的必要欄位；格式不符時在預覽階段拒絕或隔離並給明確原因。
- 只有歷史證據完整且數值一致的資料，才設計受控、可重跑、不可重複的補正；測試與正式分開授權。
- Portal顯示精確原因，例如「缺當日規格版本」「保存值與計算紀錄不一致」「僅紀錄模式」，並保留現有OK／NG行為。
- 驗收截圖至少包含：修正前原因、主檔／歷史版本依據、修正後查詢結果及未能補正清單；截圖不得含帳密、JWT或敏感設定。

非範圍：

- 本次規劃不修改程式、資料、公式、F、主檔或網站，不執行匯入／補判／發布。
- 不以目前主檔規格直接回填全部歷史，不把「無法判定」改顯示為OK，也不改原量測值。
- 不處理藥液濃度公式、F一致性工作中既有的4項NA、其他兩式或EXE交付；只引用其證據。

## 建議匯入格式

每筆至少應能提供或由系統唯一解析：

| 類別 | 必要內容 | 格式／調整建議 |
|---|---|---|
| 身分定位 | 線別、槽位、分析項目，或唯一PPC ID | 名稱須與主檔唯一對應；重名或找不到時隔離，不猜測 |
| 量測時間 | 實際量測日期時間與班別；歷史報表只有日期時須明示合成規則 | 西元／民國日期可正規化，但不可用匯入日取代量測日 |
| 數值 | 初驗值、複驗值及原始輸入Primary／Secondary | 0是有效值；空白與0分開；數字不可混入單位或全形符號 |
| 當時規格 | LSL、USL、Target及有效日，或不可變規格版本ID | 至少一個界限；LSL不得大於USL；若只提供現在規格，不足以回判舊資料 |
| 公式證據 | 公式版本、F版本／格位及引用值、計算階段 | 公式衍生濃度須保存初／複驗Phase；缺F或版本時拒絕，不以最新值代替 |
| 追溯 | 來源檔、工作表／列、批次／receipt、操作者或明確「來源未記錄」 | receipt需穩定且可防重；缺操作者不一定阻止判定，但要保留資料品質註記 |

若Excel無法提供當時規格或公式F版本，先把該列列為「待補證據」，不要只補一個OK／NG欄位；使用者輸入的判定文字不能取代伺服器驗證。

## 例外與邊界

- 規格只有單邊界限可判定；上下限皆空、非有限值或LSL大於USL不可判定。
- 複驗0必須視為有效終值，並保留初驗判定；無複驗才使用初驗。
- 目前主檔與歷史版本完全相同，也須有版本／有效日或其他權威證據才能補判。
- RECORD_ONLY資料維持不作規格判定；不得因主檔有界限就改成OK／NG。
- 來源值看似落在目前規格內，不代表濃度已正確計算；須先確認顯示的是原始滴定值、濃度或百分比及其單位。

## T-002匯入邊界與BDD

一般計量型API／Excel／CSV匯入不具備建立不可變藥液公式／F／規格證據的交易契約，因此不得接受`ControlScope=CHEM`。這類列在preview以`CHEMICAL_EVIDENCE_REQUIRED`隔離，並顯示來源檔、工作表、列號、欄位及調整建議；確認端須再次拒絕，避免部署前已建立的舊PreviewReady批次繞過新規則。

允許的CHEM寫入只有：

- Portal藥液日報專用服務在同一交易中驗證PPC、含時區量測時間、Initial／Recheck原始輸入與preview token，保存公式、F與規格證據。
- TransFiles使用既有受控公式試算／receipt及資料庫程序，提供穩定SourceKey並驗證重跑防重。

一般匯入範本不得再放可直接送出的CHEM示例，改為明示上述專用流程。

2026-11-04已完成T-002：一般匯入preview與confirm均以`CHEMICAL_EVIDENCE_REQUIRED`關閉CHEM繞過路徑，外部即使傳入`portalDaily=true`也不能取得信任；只有伺服器內部`ChemicalPortalMeasurementService`能在同一受控交易傳遞信任旗標。一般範本已移除CHEM範例，測試站API 0.1.107／Web 0.1.120完成連線驗證。未修改資料庫schema、既有量測、公式、F或正式站。

## T-003受控補正規則與BDD

T-003只修復量測列遺失的初驗Receipt連結與SourceKeyHash，不新增、修改或猜測Receipt、Trace、公式、F值、規格、測量值或判定。只有同時符合下列條件才能進入伺服器產生的manifest：

- 量測是CHEM且`ChemicalReceiptId`為空；Initial只有一筆Trace，有複驗時Recheck也只有一筆，且沒有多餘階段或版本。
- Receipt、Effectivity、Formula及Payload可由`ChemicalTraceQueryService.Read`完整驗證，PPC、量測時間、SourceKeyHash與公式證據一致。
- Initial／Recheck的Stored canonical值與現存測量值完全一致，且伺服器追溯判定為OK或NG。

manifest內容以SHA-256鎖定。Apply在Serializable交易內先逐筆重驗；任一列被改動或證據不一致時整批rollback。已連結至相同Receipt／SourceKey者回報NoChange，不重複寫入稽核記錄。

2026-11-04實際測試庫dry-run沿用網站同一歷史判定後，1,611筆Unknown中可補正0筆，1,611筆皆為`NO_TRACE_EVIDENCE`。因manifest為空，系統不允許寫入；前後量測連結指紋與各追溯表筆數一致。這些列必須由來源補回當時Receipt／Trace、公式F與規格證據，仍不可以目前主檔補判。

```gherkin

  And 測量值、PPC、時間與SourceKey全部一致
  When 管理者套用伺服器產生的manifest
  Then 只補上ChemicalReceiptId與ChemicalSourceKeyHash
  And 查詢改為SavedTrace來源
  And 重跑回報NoChange

Scenario: 無證據或證據衝突不得補正
  Given 歷史列沒有Trace或存在多筆衝突Trace
  When 系統執行dry-run
  Then 該列不在manifest
  And 修正清單提供固定原因碼與補件建議

  Given manifest建立後其中一筆量測或追溯已改變
  When 系統套用該manifest
  Then 整批失敗且不留下部分連結或稽核資料
```
