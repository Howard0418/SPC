# 正式 SPC 重複帳號整理計畫
- 功能 ID：SPC-OPERATORS-MERGE-1125
- 規格版本：1
- [規格](spec.md)｜[任務](tasks.md)｜[驗證](verification.md)

## 作業次序

1. 排到本件時，正式唯讀定位兩筆 ID、查可信 AD 帳號及工號、確認是否影響登入或授權，列出兩筆狀態與權限差異。僅同名或同 Email 時保留待確認。
2. 確認保留哪個 SPC 主檔及核准的權限。盤點實際量測、校正保管人、報表／告警／校正收件名單（含 JSON ID）及稽核引用。保留歷史稽核事件及當時的快照。維持歷史可查；可移轉的營運關聯須明列且獲核准。權限差異不得直接取聯集。
3. 先用隔離測試資料演練同人、不同身分、空白帳號、重送、並行異動及失敗回復；核對正式目標及回復方式。準備差異清單，取得正式寫入核准後再作業。
4. 正式作業在同一交易內重讀兩筆與受影響引用，套用核准的差異。隔離重複登入綁定並保留歷史識別。現行 SSO 會檢查停用紀錄，只停用但仍維持相同登入值可能繼續阻擋。若有核准的收件人移轉，移轉且去除重複 ID。
5. 用受影響帳號從 Portal 重新登入 SPC，證實搜尋標準帳號只命中指定主檔，並查回有效權限、歷史、通知及無關帳戶。實際登入無法核對時列為待驗。

## 備份及回復

正式動作前核對資料庫備份及還原路徑，保留這兩筆與受影響欄位的變更前影像。未提交時回滾交易；提交後核對當前值再按差異逐項回復，避免覆蓋其他交易。待排程的本案只預計整理正式資料，網站發布不適用。若需要程式或 schema 變更，再另依現行流程規劃、測試與發布。
