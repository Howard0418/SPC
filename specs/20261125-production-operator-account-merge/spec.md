# 正式 SPC 重複帳號整理
- 功能 ID：SPC-OPERATORS-MERGE-1125
- 版本：2
- 狀態：P1。指定組正式處理與驗收完成。確認影響登入、身分或授權時升為 P0。
- 主系統：SPC。相依系統：Portal／AD 身分來源，僅供核對。
- 授權依據：2026-11-25 使用者回報正式人員主檔兩筆相同帳號，要求先規劃入池。
- 基準：[AD／工號單一操作者](../20260917-sso-single-operator/spec.md)、[人員比對](../20261125-operator-directory-connection/spec.md)、[安全稽核](../20261123-production-security-audit/verification.md)。

## 問題與範圍

使用者回報正式「作業人員與權限主檔維護」出現兩筆相同帳號。初次回報無截圖或本案帳號識別。正式唯讀調查結果見本文補充及驗證紀錄。現有主檔儲存會去除帳號前後空白並檢查重複，SSO 則會納入裸 AD 帳號、網域前綴及 UPN；同時對到多筆會拒絕。顯示相似可能是格式差異、工號與登入帳號混用，或確有重複。既有測試區同人個案待定位後才能判斷是否相關。

處理範圍限這一組正式 SPC 主檔。Portal／AD 只作身分佐證。網站、API、schema 與批量去重不在本案範圍；若定位後發現仍可能產生新重複，再另列防重工作。

## 帳號格式與截圖

- 以 Portal／AD 認定的本人帳號為準。SPC「登入帳號」建議填不含前後空白的裸 AD 帳號；例如經確認是同人後，將 DOMAIN\account 或 account@example.com 比對為 account。工號填 CODE，通知信箱填 Email。工號或網域身分不一致時，保留原值並先查證。
- 截圖為選用佐證。建議 PNG 或清楚 JPG，保留主檔頁名、正式環境及兩列的登入帳號、工號、角色與啟用欄。遮蔽姓名、完整帳號、工號、信箱與無關人員，可保留一致的末幾碼供辨識。若只看到顯示名稱或欄位被裁掉，拉寬視窗或分兩張補齊。若有錯誤提示，另附提示及發生時間。截圖留本機，身分仍以受信來源核對。
- 排到本件後才確認兩筆身分、保留主檔、正確帳號及權限差異。正式寫入需另有明確核准。

## 正式唯讀查核補充

- 33 筆未刪除正式主檔無相同登入值、AD 正規化撞名或正規化工號重複，另有三組兩筆顯示名稱相同。三組均各一筆同時匹配正式 Portal 品保名單的 AD 與工號，另一筆以姓名作為主檔工號和登入值，皆為啟用的編輯者。使用者已從三組中指定本案；其他組別維持原樣。
- 建議保留指定組的正式 AD 主檔與原權限，核准後再隔離另一筆登入資料。正式量測的作業人員文字保留；不以姓名推定量測屬於哪個登入主檔。
- 匯入可重建類似資料的防重需求另列[匯入與登入主檔分離](../20261125-import-operator-identity-separation/spec.md)。本案維持 P1。先隱藏舊列可能使現行匯入撞到正式工號唯一約束。已先正式發布匯入防重，再退役指定非 AD 主檔。另兩組不在本次授權範圍。

## 2026-11-25 正式執行確認

使用者在測試發布及指定組核對後確認執行。先將同一匯入防重修正併入現行正式基準並發布 SPC。正式環境通過版本、健康、瀏覽器 API 與主資產查核後，才處理指定組的一筆非 AD 主檔。正式 AD 主檔、原角色及權限、通知設定、量測與既有稽核不得變更。以可回復的停用及隱藏保留舊紀錄，解除其登入綁定；若查得新的 ID 引用或帳號變動，先停止並查明。其他同名組不在本次範圍。
