# 功能規格：儀器主檔直接修改校正日期
- 功能 ID：20260914-calibration-date-edit
- 版本：1
- 狀態：可實作
- 涉及專案：SPC
- 授權依據：2026-09-14 使用者「可以直接修改校正日期」，並授權測試通過後發布 SPC release/test。
- 現行需求基準：[需求索引](../../docs/requirements.md)、[基準 3.6](../../docs/SPC_REQUIREMENTS_BASELINE_2026-08-07.md)
- 前案：[校正模組](../20260911-instrument-calibration/spec.md)、[日期後補](../20260912-calibration-import-pending-dates/spec.md)

## 目的、現況與證據
操作：儀器校正到期管理 → 操作/編輯 → 調整日期 → 儲存儀器。InstrumentCalibrationsView 可改上次日期，PUT 原樣送出；InstrumentCalibrationService.SaveInstrumentAsync 對任何既有主檔 LastCalibrationDate 變化（含 null 補填）都拋出「上次校正日期請透過新增校正紀錄維護」。
前案原則為校正歷史只追加；後續已確認日期可空、先匯入後補。本次使用者明確授權直接修改日期，因此主檔日期可更正，歷次校正紀錄仍不可覆寫。先前助理建議的「只限首次補填」未被採用，不應當成本次限制。
基準 3.6 已載明下次可空；其較舊匯入段落仍稱下次必填/未發布，與已確認後案不一致，本次同步該相關範圍，保留歷史規格。

## 範圍與非範圍
開放既有儀器主檔上次校正日的修改/補填/清空，下次日期維持既有直接編輯規則。無新 API、schema migration。保留亮色介面、匯入/放置地點/校驗方式、量測與通知排程。無正式發布、真信或真實資料批次修補。

## 需求與驗收
| 需求 ID | 業務規則 | 驗收 ID | 可觀察的通過條件 |
|---|---|---|---|
| R-001 | 管理者可直接修改既有主檔上次日期，不限首次補填或無歷史；上次/下次依既有可空規則 | AC-001 | null→日期、日期→日期、日期→null 都可儲存，GET 回傳新值 |
| R-002 | 保留日期驗證：上次不可未來；兩日期有值則下次必須晚於上次 | AC-002 | 不合法請求拒絕且資料、稽核及通知均不變 |
| R-003 | 修改主檔不建立合格校正、不更動歷次紀錄/證書/LatestResult/CurrentCycleId；下次不自動重算 | AC-003 | 已有校正歷史仍可修改，歷史及結果保持原值；稽核保存操作者/時間/前後日期 |
| R-004 | 下次已有值再修改仍必填理由並取消 Pending/Failed，Sent 保留；只改上次不動到期通知 | AC-004 | 到期日/通知防重行為與前案相同，單改上次不開新週期或重寄 |
| R-005 | 保留 Editor＋calibration.manage 授權與 Version 競爭保護；不改日期的其他欄位仍可存 | AC-005 | Viewer/無管理權限拒絕；舊 Version 409；其他欄位儲存成功 |
| R-006 | 表單說明直接編輯是主檔更正，非登記校正結果；維持既有改期理由提示 | AC-006 | 日期修改 PUT 成功、列表更新，必要錯誤保留於表單 |
| R-007 | 通過測試與建置後備份並發布測試站；同步需求/驗證/發布證據 | AC-007 | test 環境及 PMR_SPC_TEST 核對、設定保留、程式 hash 與健康檢查通過 |

## 例外與邊界
上次修改不新增理由必填門檻；可填原因並由既有 InstrumentUpdated 稽核記錄。下次日期的理由規則不放寬。校正紀錄維護端點的日期/結果判斷不在本次修改範圍。無日期儀器不列摘要、不寄通知的規則保留。

## 假設與未決問題
「編輯儀器主檔tmb toh」中的尾碼視為輸入雜字，操作路徑已明確。無阻擋問題；使用者明確的新要求優先於舊程式限制。
