## 系統責任與受影響檔案
- SPC API：管制圖類型、落塵資料查詢、CA/CPK 計算、分段規格、F 表公式資料。
- SPC Web：落塵監控選項、U-chart/C-chart 顯示、CA 顯示、分段規格線、公式追溯畫面或查詢結果。
- SPC DB：可能新增落塵主檔、規格歷史、F 表公式版本與適用範圍資料表。
- TransFiles：Excel 解析、預覽、錯誤列、確認匯入與 SPC API 呼叫。
- 測試：後端單元/整合測試、前端測試、TransFiles 匯入測試。

## 實作方式與需求對應
1. 盤點既有 U-chart/C-chart、CA/CPK、規格主檔、TransFiles 匯入與 F 表公式流程。
2. 依盤點結果先建立測試與資料契約，再實作最小變更。
3. 落塵監控採固定 1um、5um 匯入，預覽先行，確認後才寫入。
4. CA 顯示與 CPK 計算分離，避免顯示規則改變能力指標。
5. 分段規格以生效日套用量測點，圖表回傳每段規格線與每點套用規格。
6. F 表公式先以 dry-run 顯示差異與受影響線別，再進行受控寫入。

## 盤點後建議順序
1. 確認阻擋性業務資料：落塵 Excel 版型、U-chart 分母、F 表正式來源。
2. 先做低耦合變更：CA 有號顯示與 CPK/Ppk 回歸測試。
3. 再做資料結構：分段規格、F 表版本/引用索引、必要時新增落塵主檔。
4. 再做 SPC API 與 Web：落塵 Attribute 查詢/顯示、分段規格線、F 表影響查詢。
5. 最後做 TransFiles 落塵匯入，接到已穩定的 SPC API。

## API、檔案格式及資料模型
- 落塵 Excel：固定讀取 1um、5um 欄位；日期、來源檔名、列號、匯入批次需可追溯。
- 管制圖 API：需能回傳落塵監控資料、圖型、點位、UCL/CL/LCL、分段 LSL/USL/Target。
- 能力指標 API：CA 可為正或負；CPK 維持既有公式或等價結果。
- 分段規格：至少需包含 PPC、LSL、Target、USL、生效日、版本/建立資訊。
- F 表公式：至少需包含公式代碼、公式內容、版本、來源、適用線別/槽位/分析項目、建立/異動資訊。

## 相容性與風險
- U-chart 需要分母，若來源 Excel 未提供，需先確認業務規則。
- 分段規格會影響歷史圖表，不可讓舊資料被目前主檔規格誤判。
- CA 改顯示正負號可能影響週月報表或前端格式化。
- F 表寫入系統若與既有項目專屬公式重疊，需避免覆寫已確認客製化設定。
- TransFiles 匯入需保留既有藥液與咬蝕流程。
