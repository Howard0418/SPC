# 技術計畫

- 功能 ID：SPC-HISTORICAL-IMPORT-1102
- 規格版本：1
- 規格：[spec.md](spec.md)

## 系統責任與受影響檔案

SPC 負責主檔核對、量測寫入、計算與兩類圖表；TransFiles 僅在已確認需要時負責原始檔唯讀解析／preview，不得取代 SPC 的正式環境守衛。Portal 不在本次資料寫入範圍。執行時才會建立 task 專用 manifest、dry-run 與驗收證據；不先改產品程式或設定。

## 實作方式與需求對應

1. TASK-001 建立來源 manifest：檔案雜湊、日期、工作表、資料類型、來源鍵、筆數與格式錯誤清單。
2. TASK-002 先在測試庫以同一 manifest 做 preview／受控小批匯入、逐筆對帳與防重跑；確認管制圖／趨勢圖候選驗收矩陣。
3. TASK-003 只做正式 preflight：核對正式環境標籤與資料庫、主檔／公式／規格、既有衝突、備份與 `VERIFYONLY`。未取得正式 apply 授權不得寫入。
4. TASK-004 在明確正式 apply 授權後才可執行；先備份、再僅新增、後逐筆／圖表／重跑驗收，保留可依批次追溯的回復與證據。

## API、檔案格式及資料模型

沿用現有匯入 API／資料模型與來源鍵；不新增 schema。來源至少需提供可判定的量測日期、PPC 或可唯一映射的特性、數值、單位／階段（如該類型需要）、及原始定位。格式不符合時輸出「檔案／sheet／列欄／原值／預期／建議」五欄報告。

## 相容性與風險

正式資料寫入是高風險且不可與其他 schema、權限、IIS 或正式資料工作併行。採 immutable manifest、僅新增、交易、環境雙重確認、備份與同鍵衝突停止。不得以測試資料列／ID／批次複製到正式，亦不得自動修正主檔或格式。

## 驗證安排

TASK-001：來源讀取、格式、日期涵蓋與雜湊。
TASK-002：Happy path、0／邊界、重複、缺欄／無效數值、跨日／跨月；逐筆對帳與兩類圖表查詢。
TASK-003：錯環境、衝突、缺主檔、備份失敗均須在寫入前拒絕。
TASK-004：正式逐筆／筆數／資料前後指紋、圖表點數與數值、重跑零新增；每月各管制圖及趨勢圖至少一組 UI 截圖，並記錄 API 對帳。

## 發布、備份及回復

本案不預計發布網站；若執行中發現產品缺陷，另建最小修正 task，測試通過後才依規範發布測試站。正式資料匯入前，必須另取得明確 apply 授權並完成備份／`VERIFYONLY`；回復依本次新建的 batch／來源鍵作受控處置，禁止未核對即刪除資料。
