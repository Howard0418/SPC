# 共用 SDD 開發流程
版本：1.1｜生效：2026-09-09｜主文件位於 D:/SPC/docs/sdd-workflow.md

## 適用與導入狀態
SPC、PmrPortal、TransFiles、KM、Chameleon、DH_Temperature、python-pypxlib、PMR_ERP撈取工單、DS2000、Voice 已接入同一文件流程；各專案範圍見 [導入登錄](sdd-projects.md)。DS2000 僅確認 Ri320Bridge 原始碼，Voice 僅建立活頁簿需求入口。
本次完成流程文件導入；下一個真實功能需求仍須完整試行並回顧。既有程式不補造歷史規格、測試或核准紀錄。

## 開工入口
1. 閱讀所在專案 AGENTS.md、docs/requirements.md、需求相關變更紀錄及本文件。
2. 確認需求所屬專案、現有行為與使用者要求。只讀取相關文件與程式。
3. 比對需求基準與較新的變更紀錄；若不一致，列出差異與依據。明確已確認的新需求應同步基準；不能僅依日期推定所有紀錄皆可取代基準。會影響實作且無法判定的業務衝突才詢問使用者。
4. 在 specs/ 建立功能規格後才實作。使用者本次及先前授權持續有效，規格、計畫、任務可連續完成，沒有逐階段強制批准。
5. 資訊不足但不影響當前工作時，記錄假設並繼續；未決業務規則不能自行當成已確認需求。

## 文件分工與命名
- docs/requirements.md：現行業務需求或其權威索引。沿用原有基準，不複製另一份。
- specs/YYYYMMDD-短名稱/：本次變更，使用唯一功能 ID，跨專案一致。
- spec.md：目的、範圍、非範圍、現況及證據、需求 R-xxx、驗收 AC-xxx、未決問題、狀態與規格版本。
- plan.md：受影響檔案與系統、實作方式、API/資料模型、相容性、驗證及發布安排。
- tasks.md：任務對應需求/驗收編號，只有真正完成才勾選。
- verification.md：驗收編號對應執行方式、結果與證據。未執行必須註明，不能寫通過。
- CHANGELOG_CUSTOM.md：已完成變更與回歸結果；不能取代現行需求基準。
範本見 [templates/sdd](templates/sdd/spec.md)。

## 流程與規模
規格 → 計畫 → 任務 → 實作 → 對照驗收 → 更新基準與變更紀錄。
- 低影響文案、樣式、簡單修正：可用一份 spec.md 合併計畫、任務及驗證，採 [small-change 範本](templates/sdd/small-change.md)。
- 新功能、公式、API、權限或資料寫入變更：使用完整四份文件。
- 跨專案、schema migration、正式資料修補：完整文件另列相容性、環境、發布順序、備份與回復方法。
- 流程文件導入可使用完整四份文件示範追溯，但不代表業務功能驗收。
- 緊急修正至少先記錄問題、預期行為與驗證條件，再修改；收尾補齊必要紀錄。
實作中需求改變：先同步規格版本及受影響計畫/任務，再繼續。已完成規格保留歷史；後續變更建立新規格並引用前案。

## 驗證及完成定義
依變更影響決定檢查：文案/文件採內容、連結或畫面檢查；計算、權限、資料處理採對應行為測試及相關回歸。
遵守既有專案必要測試要求；不為文案等低影響修改新增鏡像測試。
完成須符合：需求與驗收可追溯、必要任務完成、必要檢查通過、有效需求及變更紀錄同步。
有未執行的必要驗收時，標示「待驗證」，不得標示完成。
分別記錄實作、驗證、發布狀態；無應用程式變更的文件工作，發布標示「不適用」，不執行建置/IIS 發布。
應用程式發布依當次授權及專案規範執行；以實際環境設定確認目的地，不直接沿用可能過時的文件路徑。

## 跨專案規格
SPC/Portal/TransFiles 整合需求以 SPC specs/ 的一份主規格為準；其他專案只建立引用索引，包含功能 ID、主文件位置及版本。
主規格列出各系統責任、API/檔案契約、各自任務與端到端驗收。獨立 Portal 或 TransFiles 功能仍在自己的 specs/ 管理。
跨專案更動限使用者需求授權範圍。TransFiles 獨立轉檔需求不隱含修改 Portal/SPC。

## 基準及維護
流程主文件與範本只在 SPC 維護；其餘專案使用指向主文件的入口。跨磁碟路徑為目前工作區配置，搬移後須更新索引。
若主文件不可讀，先恢復正確位置；不得自行建立互相分歧的流程副本。
現有程式行為僅是觀察，未確認時標示待確認，不直接升格為業務要求。
流程版本更新時檢查所有已接入專案入口與既有規則衝突。

## 下一次功能試行
選取使用者實際提出的一個需求，建立新功能規格，執行對應測試與必要端到端驗收。
回顧文件量、需求衝突、跨系統遺漏與證據完整性，再逐步補齊各專案的業務基準。
不以本次文件導入取代真實功能試行。
