## 必須同步的內容

1. 更新截至日期、工作項目及功能範圍；分列開發／測試、人工驗收與正式狀態。測試通過不等於正式發布，暫緩／受阻不得標完成；最新功能未正式發布仍須保留待辦。
2. 同步有依據的實際紀錄起訖日期與日期軸，並實際調整對應的原生甘特條／里程碑位置；不能只改摘要、版本號或新增文字區。起訖日用Excel日期值並標明年份；三系統目前均從2026-10-01逐日顯示，10月以前不佔用圖面。以台灣日期為準，跨月／跨年與最後截點要正確。
3. 目前基準為2026年實際進度，截至2026-10-27；後續按工作實際日期推進，跨年必須延展至正確年份，不固定沿用2026或10/27。圖面保留十月起始基準並按需要向後延展；跨顯示起點的條從10/1裁切，顯示期前完成的里程碑不搬到10月，原始日期仍保留在紀錄欄。未來日期僅顯示空格，不畫成實際完成進度。
4. 區分「已查證紀錄涵蓋期間」與「完整開發工期」。未知全案起日、預計日、百分比明示待確認，不拿文件檔名日期、量測資料日期或色條長度反推開發起訖；單日事件畫里程碑，不補造期間。有新證據才修正日期與來源。
5. 保留SPC原10階段、Portal原3群組及KM功能明細的追溯、主責、圖例與來源。Portal負責入口／量測輸入，SPC負責主檔／儲存／運算／圖表，KM負責知識／文件治理與訓練，TransFiles仍為獨立工具。三系統摘要及同表明細一起維護，彼此既有內容只在本件涉及時更動；其餘專案原文字／排程／原生物件保留。不要以舊計畫（例如KM預計2027開案）覆蓋較新已確認的正式紀錄。
6. 同一活頁簿「小工作總表」同步登錄中央已追蹤的所有具名小工作，包含SPC／Portal／KM／TransFiles來源，保留完成紀錄；每次新增、完成、暫停、恢復或核銷本件工作時，更新其代號、內容、狀態、日期證據、來源及目前待辦旗標。以系統＋完整代號去重，父批次不和已拆子件雙計；來源只有泛稱／計數時不得虛構工作代號或排程。其他專案來源不足要明示，不當成零待辦。
7. 「目前待辦＝是」為核心未完成計數，包含暫停／受阻／待確認；已完成小工作、人工驗收註記、來源待核銷分開統計，不能用總列數當未完成件數或開發完成率。正文更新時連同總表公式及來源狀態核對，舊的20包／4件等歷史計數不得覆蓋最新明確紀錄。已完成但仍有人工限制者另留註記，不為登錄自動恢復開發、故障驗收、正式發布或工具打包。

## 備份、驗證與取代

1. 先確認原檔可讀、未遭其他程序修改；在同目錄「備份」保存唯一檔名與雜湊，再於工作副本修改。若檔案鎖定、遺失或另有未保存變更，保留原檔，記錄受阻原因及待補項，不以失敗輸出覆蓋。
2. 使用當次適用的試算表技能及作者工具，保留可編輯原生圖形，不以截圖回填。只調整本件涉及系統的日期／條形及必要版面；對來源原生物件的相容性保留措施須可核對。三個repo可能同時處理工作，更新前後須確認原檔未變，不覆蓋另一工作的結果；必要時合併最新內容後重驗。
3. 比對已變更的日期、週軸、起迄順序與截點、甘特條錨點／範圍、單日標記；檢查其他專案內容及原生圖形不變。未來預計日期若另有明確授權，須與實際日期分開，不能顯示為已完成。
4. 通過ZIP封裝與OpenXML SDK結構驗證（0錯誤）、重新開啟／渲染及列印版面檢查；禁止重複的同表Print_Area、rowBreaks與缺少content type或關聯的part。重跑更新不能累加重複列印設定。只有預覽可渲染或LibreOffice可開啟，不足以宣稱Excel格式相容。
5. 驗證通過後再核原檔未變，取代指定原路徑，核對輸出雜湊並從原路徑重讀。若驗證失敗則保留原檔及必要備份，修正後重驗；不可標示進度表同步完成。需復原時以對應更新前備份覆蓋。
6. 驗證紀錄如實區分OpenXML自動驗證、渲染／列印及Microsoft Excel人工開啟；未做人工就明示未做，不冒稱人工驗收通過。
